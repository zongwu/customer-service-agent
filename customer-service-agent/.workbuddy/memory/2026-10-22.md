## 客服 RAG Agent 骨架搭建（rag/ 检索层完成）

用户需求：Chroma + 中文 BGE Embedding + BM25 + RRF + Cross-Encoder 重排，
后续接 DeepSeek。已建目录骨架并完整实现 rag/ 全部 9 个文件。

### 技术决策

- **RRF 融合而非分数加权**：Chroma 余弦相似度与 BM25 分数不同量纲（BM25 无上界），
  硬归一化会被离群值主导；RRF 只吃排名，无需调权重。
- **BGE Embedding 必须 normalize_embeddings=True**：余弦检索下归一化后点积才等价于余弦。
- **BM25 对零分文档不返回**：零分候选会污染重排。
- **preprocessor 只喂 BM25**：Embedding 自带分词器在完整语义上表现更好，
  人工分词反而损失信息。
- **agent/ 目录按要求建好但留空**：客服问答是「检索+单次生成」，不需要自主 Agent
  循环（C3 判断）。接 DeepSeek 时用线性 StateGraph 即可，不要加 planner/reflection。

### 踩坑：切片退化（重要）

初次实现直接用 RecursiveCharacterTextSplitter 切 250 字知识库，
结果**全部合成 1 个 chunk**，混合检索完全失效
（BM25 对任意 query 都返回同一块，RRF/重排无从发挥）。

原因：splitter 会贪心合并各级分隔符碎片直到填满 chunk_size=300，
全文短于 chunk_size 时必然合并成一整块。

修复：loader 先按空行切成问答块，单块超长才递归细切。修复后 4 块，
BM25 top-1 精确命中且不含干扰主题。

**教训**：知识库短于 chunk_size 时必须显式按语义边界预切，
并加"切片粒度"测试拦截退化。已加 `test_chunking()` 与
端到端断言里的 `must_not` 反向断言（防假阳性）。

## 排查：torch 加载 WinError 126（shm.dll）

用户在系统 Python（`C:\Users\HP\AppData\Local\Programs\Python\Python313`）跑测试报错：
`OSError: [WinError 126] 找不到指定的模块。Error loading "...torch\lib\shm.dll"`

### 排查过程与结论

逐层排除，**不是代码问题，是环境问题**：

1. `shm.dll` 文件存在，VC++ 运行库齐全（msvcp140/vcruntime140 均在，14.40 版本）
   → 排除"文件缺失"和"运行库缺失"
2. 提交内存曾达 97.8%（16GB 机器，仅剩 671MB 虚拟内存）→ **首要嫌疑**
3. 内存释放到 76.4% 后 torch **仍然失败** → 内存不是唯一原因
4. 自写PE 导入表解析器（`_pe_deps.py`，纯 Python 无依赖）：
   - `shm.dll` 外部依赖 **0 个**（15KB 零依赖 DLL 也加载失败）
   - `torch_cpu.dll`（305MB）同样 0 外部依赖
   - 对照组 `c10.dll` 加载成功
   → **零依赖却失败，排除依赖缺失，指向安全软件拦截**
5. 所有 torch 文件创建时间均为**当天 23:08**，`shm.dll` 无数字签名
   （`Get-AuthenticodeSignature` → NotSigned）
   → 符合"pip 装完后被安全软件隔离/拦截新 DLL"的特征

### 关键认知（重要，勿忘）

**WinError 126 在这里极具误导性**：字面是"找不到指定的模块"，
实际两种完全不同的根因：
- 大 DLL 映射时提交内存不足 → 报 126
- 安全软件拦截无签名新 DLL → 报 126

两者都**不是文件损坏**，所以"重装 torch / 降级版本"是纯浪费。
必须用 PE 导入表解析才能定性。
